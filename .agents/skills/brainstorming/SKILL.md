# Brainstorming

## Trigger

Use when requirements are unclear, product direction is undecided, or the user asks "how should we".

## Do Not Trigger

Do not use when the user has already approved a concrete implementation.

## Input

- Problem statement.
- Constraints and user skill level.

## Output

- 2-3 options.
- Tradeoffs.
- Recommended next step.

## Steps

1. Clarify the real user outcome.
2. Offer 2-3 small options with pros/cons.
3. Recommend one option based on FREETEXT principles.
4. Wait for approval before code if the choice materially changes product direction.

## Acceptance

- Options are concrete and executable.
- Recommendation is clear.

## Common Failures

- Listing abstract concepts.
- Offering too many choices.

## Relationship To AGENTS.md

Implements the AGENTS.md rule that ambiguous needs get 2-3 options before coding.
