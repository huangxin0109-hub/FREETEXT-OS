# FREETEXT OS、FREETEXT Bookstore OS、AI选书官三者关系说明 v1.0

> 当前阶段：产品关系定义与真实场景验证准备  
> 本阶段不开发功能，只明确三者边界、推进顺序和验证方法。

## 核心结论

**FREETEXT OS 是母系统。**  
**FREETEXT Bookstore OS 是第一个行业子系统。**  
**AI选书官是第一个可落地功能模块。**

三者不是互相竞争的三个产品，而是从大到小、从长期方向到近期验证的一套产品结构：

**FREETEXT OS（母系统） → FREETEXT Bookstore OS（书店行业子系统） → AI选书官（第一个功能模块）**

这套结构必须长期保持清楚。母系统决定共同方法，行业子系统承接书店场景，功能模块解决一个具体问题。

## 1. FREETEXT OS 是什么

FREETEXT OS 是面向文化行业和非程序员创业者的 AI 项目落地母系统。

它帮助用户把一句模糊想法变成：

- 清楚的项目定义。
- 可以保存的项目文件。
- 当前阶段判断。
- 最重要的下一步行动。
- 可以持续更新的项目知识库。

FREETEXT OS 不是只服务书店，也不是一个普通聊天工具。它未来可以服务阅读空间、企业文化、展览活动、文化商业空间和其他文化项目。

母系统负责沉淀所有行业都可以共同使用的方法：

**输入想法 → 理清需求 → 形成文件 → 拆成动作 → 持续推进。**

母系统当前的第一任务不是开发很多功能，而是通过一个真实行业场景证明这套方法可以落地。

## 2. FREETEXT Bookstore OS 是什么

FREETEXT Bookstore OS 是 FREETEXT OS 在书店与阅读空间行业中的第一个子系统。

它把母系统的通用落地方法，放进书店的真实经营场景中使用，例如：

- 书店定位和主题方向。
- 选书与书单整理。
- 阅读空间内容规划。
- 书展、展台和主题陈列。
- 书店活动与文化内容策划。
- 企业阅读空间方案。
- 书店项目的下一步行动和知识沉淀。

选择书店作为第一个行业子系统，是因为 FREETEXT 已经拥有真实书店、阅读空间、文化活动和商业项目经验。这比从陌生行业开始更容易验证，也符合先服务自身真实项目、再形成外部产品的商业路径。

FREETEXT Bookstore OS 当前不是一个要立刻做全的“大型书店系统”。它首先是一个验证范围：用书店行业中的真实问题，检验 FREETEXT OS 的方法是否有价值。

## 3. AI选书官是什么

AI选书官是 FREETEXT Bookstore OS 中第一个可以被理解、被演示、被真实验证的功能模块。

它要解决的不是“推荐一些热门书”，而是帮助一个具体用户，围绕一个具体目标，形成一份有理由、有结构、可以使用的选书结果。

AI选书官可能服务的真实任务包括：

- 为一家书店确定主题书单。
- 为企业阅读空间准备选书方案。
- 为展览、活动或品牌联名生成配套书单。
- 根据目标人群、空间主题和预算整理候选书目。
- 说明每本书为什么被选择，以及下一步如何使用这份书单。

AI选书官的最小输出建议包括：

- 选书目标。
- 服务对象。
- 书单主题和结构。
- 候选书目及选择理由。
- 下一步核对和执行动作。

**待确认：** 第一位真实使用者、首个选书任务、可用书目来源、预算范围，以及最终交付文件的格式。

## 4. 为什么它们不是互相冲突的三个产品

三者解决的是不同层级的问题。

| 层级 | 名称 | 负责什么 | 当前作用 |
| --- | --- | --- | --- |
| 母系统 | FREETEXT OS | 提供文化项目从想法到执行的共同方法 | 保持长期方向一致 |
| 行业子系统 | FREETEXT Bookstore OS | 把共同方法应用到书店和阅读空间 | 提供第一个真实行业场景 |
| 功能模块 | AI选书官 | 解决书店场景中的一个具体任务 | 提供第一个可验证入口 |

它们之间不是“选择谁、放弃谁”的关系，而是“谁包含谁、谁验证谁”的关系。

- 没有 FREETEXT OS，AI选书官容易变成一个孤立的推荐工具。
- 没有 FREETEXT Bookstore OS，AI选书官产生的书单难以继续进入空间、活动和运营流程。
- 没有 AI选书官，FREETEXT OS 和 Bookstore OS 容易停留在宏大概念，缺少可以立刻验证的具体入口。

因此，正确关系是：母系统提供方向，子系统提供场景，功能模块提供真实结果。

## 5. 为什么 AI选书官是 FREETEXT OS 的第一个真实验证场景

AI选书官适合作为第一个验证场景，主要有六个原因。

### 5.1 与 FREETEXT 已有经验直接相关

FREETEXT 已经拥有书店、阅读空间、艺术书展、企业阅读空间和文化活动经验。选书不是凭空创造的新方向，而是已有业务能力的自然延伸。

### 5.2 用户容易理解

“告诉我需求，得到一份有理由的书单”比“使用文化项目操作系统”更容易理解和传播。

### 5.3 输入和输出比较清楚

用户可以提供主题、对象、场景和预算，系统可以输出书单、理由和下一步。这适合验证 FREETEXT OS 的核心路径：

**输入需求 → 整理判断 → 形成文件 → 给出下一步。**

### 5.4 可以先用人工与 AI 协作验证

当前不需要先开发完整功能。可以由用户提供真实需求，AI 根据现有知识整理选书方案，再由用户核对专业判断。这样能先验证价值，再决定是否开发。

### 5.5 可以连接真实业务

一份选书方案可以继续进入企业阅读空间、书店陈列、活动策划、展览和品牌合作，不只是一次性聊天结果。

### 5.6 可以检验母系统的关键能力

AI选书官能够检验：

- AI 是否理解真实文化场景。
- 输出是否能形成可用文件。
- 下一步动作是否清楚。
- 用户是否愿意继续反馈和使用。
- 经验是否能沉淀成可复用知识。

## 6. 为什么当前可以双发并行，但必须采用“一主一子一模块”结构

当前可以双发并行，是因为需要同时表达长期方向和近期落地入口。

### 可以并行发布的两条表达线

- **主线表达：FREETEXT OS**  
  对外说明长期愿景：这是帮助文化项目从想法走向执行的 AI 母系统。

- **子线表达：AI选书官，由 FREETEXT Bookstore OS 提供**  
  对外说明当前具体入口：先从一个真实、容易理解的书店场景开始验证。

“双发并行”指的是可以同时发布、介绍和收集反馈，不是同时开发三个独立产品。

必须使用“一主一子一模块”结构，是为了避免三个风险：

1. 避免外界误以为 FREETEXT 同时启动三个无关项目。
2. 避免内部为三个名字分别建立重复方案、知识库和开发任务。
3. 避免 AI选书官做大后偏离 FREETEXT OS 的长期方向。

统一对外关系建议：

- FREETEXT OS：母品牌和母系统。
- FREETEXT Bookstore OS：书店行业方案名称。
- AI选书官：第一个可以体验和验证的功能名称。

所有发布都应明确写出三者关系，不单独把 AI选书官描述成一个与 FREETEXT OS 无关的新项目。

## 7. 主线和子线分别怎么推进

## 7.1 主线：FREETEXT OS

主线负责长期产品方向和共同方法，不急着开发大量功能。

当前只推进：

- 保持并完善母系统主 PRD。
- 明确所有子系统共同遵守的 001、002、003 原则。
- 记录 AI选书官验证过程中产生的共同方法。
- 判断哪些经验可以复制到活动、空间和企业文化项目。
- 每周根据真实验证更新母系统结论。

主线当前成功标准：

- 能清楚说明 FREETEXT OS 是什么。
- 能解释为什么第一个验证场景是 AI选书官。
- 能从真实验证中沉淀一套可复制的方法。

## 7.2 子线：FREETEXT Bookstore OS 与 AI选书官

子线负责把母系统放进书店场景中验证。

当前只推进：

- 选择一个真实选书任务。
- 明确谁提出需求、为什么需要书单、书单将用于哪里。
- 用人工与 AI 协作完成第一份选书方案。
- 请真实使用者核对结果是否有用。
- 记录过程中的问题、时间和修改意见。
- 把有效步骤沉淀成可重复使用的选书流程。

子线当前成功标准：

- 完成一份被真实使用的选书方案。
- 用户能说明这份方案解决了什么问题。
- 用户愿意继续使用或愿意为类似服务付费。
- 验证结果能够反向更新 FREETEXT OS 的产品定义。

## 8. 当前阶段不应该做什么

为遵守 001、002、003 原则，当前不应该：

- 把三者当成三个独立产品分别开发。
- 同时制作三个网站、三个账号体系或三套知识库。
- 直接开发完整书店管理系统。
- 直接开发复杂 AI 推荐功能。
- 一开始就连接大量书目、库存和销售数据。
- 同时服务书店老板、普通读者、企业客户和出版机构等多类用户。
- 同时做选书、购书、库存、支付、会员、社区和活动系统。
- 在没有真实选书任务前讨论复杂技术方案。
- 只生成漂亮书单，却不说明选择理由和下一步用途。
- 把 AI选书官做成普通聊天推荐工具。
- 为三个名称分别制定互相冲突的品牌方向。
- 在中文真实场景未跑通前建设复杂国际化版本。

当前判断标准仍然只有一个：

**这件事是否能帮助完成并验证第一份真实选书方案？**

不能直接帮助验证的事情，暂时不做。

## 9. 接下来 7 天建议做什么

未来 7 天目标：不开发功能，完成 AI选书官的第一次真实人工验证，并把结果沉淀回 FREETEXT OS。

### 第 1 天：确认三者关系和对外说法

- 确认“一主一子一模块”结构作为统一口径。
- 用一句话分别说明 FREETEXT OS、Bookstore OS 和 AI选书官。

### 第 2 天：选择第一位真实用户

- 只选择一位近期确实需要选书方案的人或项目。
- 写清楚他为什么需要书单，以及书单将用于哪里。

### 第 3 天：明确第一份选书任务

- 与真实用户确认主题、目标对象、使用场景和大致数量。
- 记录仍需确认的信息，不扩大任务范围。

### 第 4 天：人工与 AI 协作形成第一版方案

- 使用现有资料和 AI 整理第一份选书方案。
- 每本或每组选书都说明选择理由和使用建议。

### 第 5 天：请真实用户核对

- 把方案交给真实用户查看。
- 只记录三个问题：哪里有用、哪里不准确、还缺什么。

### 第 6 天：整理验证结果

- 根据反馈修改方案。
- 写下完整过程、最费时间的步骤和可以重复使用的步骤。

### 第 7 天：决定是否进入下一阶段

- 判断 AI选书官是否真正解决了一个选书问题。
- 判断该流程是否值得再次使用或形成付费服务。
- 把验证结论更新为 FREETEXT OS 后续产品设计的依据。

7 天结束时应得到：

- 一份统一的“一主一子一模块”对外说法。
- 一位明确的真实用户。
- 一个明确的真实选书任务。
- 一份被真实用户核对过的选书方案。
- 一份用户反馈记录。
- 一份可重复的选书流程。
- 一个是否值得进入下一阶段的明确判断。

## 最终判断

FREETEXT OS 的长期目标很大，但第一步必须很小、很真实。

当前最合理的路径是：

**用 AI选书官解决一个真实选书问题，验证 FREETEXT Bookstore OS 的行业价值，再把有效方法沉淀回 FREETEXT OS 母系统。**

这样既保留长期方向，又能从一个具体结果开始落地。
