# AI选书官原型流程文档 v0.1

> 所属产品：FREETEXT Bookstore OS  
> 所属母系统：FREETEXT OS  
> 功能模块：AI选书官  
> 当前阶段：原型流程，不写代码  
> 核心原则：AI做苦活，人做判断

## 1. 一句话定义

AI选书官是 FREETEXT Bookstore OS 的第一个功能模块，用来帮助自由文本书店完成候选书收集、初筛、分级、解释和规则沉淀。

它不是自动采购系统。

它的核心价值是：

> 把玄石长期形成的选书经验，转化为可以被 AI 执行、被人复核、被持续优化的工作流。

## 2. 为什么现在进入原型阶段

AI选书官已经完成两轮无代码人工验证：

| 轮次 | 测试重点 | 人工反馈 |
| --- | --- | --- |
| 第1轮 | 文史哲、社科、非虚构方向 | AI 与玄石 ABC 判断完全一致；问题是文学样本偏少 |
| 第2轮 | 提高文学样本比例，测试文学气质判断 | AI 判断继续与玄石完全一致 |

因此，当前可以从“验证判断逻辑”进入“设计产品原型流程”。

但注意：

- 现在仍不写正式代码。
- 现在仍不做自动采购。
- 现在只设计最小可用流程。

## 3. 产品核心原则

### 3.1 AI做苦活

AI负责：

- 收集候选书。
- 整理书目信息。
- 判断类别。
- 按规则打 A/B/C/D 等级。
- 写推荐理由。
- 写风险提醒。
- 判断是否需要人工复核。
- 沉淀新增规则。

### 3.2 人做判断

玄石或书店负责人负责：

- 最终是否进入候选清单。
- 最终是否采购。
- 判断 AI 是否符合自由文本气质。
- 标记 AI 的错误。
- 批准规则进入规则库。

### 3.3 不追求一步到位

第一版原型只解决一个问题：

> 每月为自由文本书店生成一批值得复核的新书候选清单。

## 4. 第一版用户是谁

第一版用户不是普通读者。

第一版用户是：

- 自由文本书店经营者。
- 选书负责人。
- 未来可扩展到独立书店主理人、文化空间运营者、企业阅读空间负责人。

第一版先服务内部真实业务，不急着对外销售。

## 5. 第一版核心场景

每月选书。

用户想知道：

- 最近有哪些书值得看？
- 哪些书适合自由文本？
- 哪些书虽然有价值但不适合马上进？
- 哪些书明显不该进？
- 为什么？

## 6. 最短用户路径

```text
进入 AI选书官
↓
选择“生成本月候选书”
↓
AI根据规则收集候选书
↓
AI输出 A/B/C/D 分级清单
↓
人逐本复核：同意 / 修改 / 不接受
↓
系统生成最终候选清单
↓
沉淀本轮新增规则
```

## 7. 第一版最少页面

### 页面1：首页 / 本月选书入口

用户在这里做什么：

- 点击“开始本月选书”。
- 查看上次选书结果。
- 查看当前规则版本。

AI在这里做什么：

- 提醒当前选书周期。
- 提醒本月重点类别。
- 展示是否已有候选池。

为什么必须存在：

- 让用户一进来就知道下一步做什么。

可以删除的功能：

- 社区。
- 大屏数据。
- 复杂导航。
- 营销内容。

### 页面2：候选书生成页

用户在这里做什么：

- 选择候选来源。
- 设置本轮样本结构。
- 点击“生成候选书”。

AI在这里做什么：

- 收集候选书。
- 填写书名、作者、出版社、出版时间、类别、简介等基础信息。
- 标记信息是否完整。

为什么必须存在：

- 第一版不能让玄石手工收集书单。AI必须承担苦活。

可以删除的功能：

- 复杂爬虫设置。
- 多平台账号绑定。
- 自动采购接口。

### 页面3：AI初筛结果页

用户在这里做什么：

- 查看 A/B/C/D 分级。
- 查看推荐理由。
- 查看风险提醒。
- 快速筛选 A、B、C、D。

AI在这里做什么：

- 给每本书评级。
- 解释为什么推荐或不推荐。
- 标记库存、出版信息、定价等待确认项。

为什么必须存在：

- 这是 AI选书官的核心价值页面。

可以删除的功能：

- 花哨卡片动画。
- 复杂图表。
- 社交分享。

### 页面4：人工复核页

用户在这里做什么：

- 对每本书点选：同意 / 修改 / 不接受。
- 写一句人工理由。
- 确认是否进入候选清单。

AI在这里做什么：

- 记录人工反馈。
- 识别分歧原因。
- 建议新增或修改规则。

为什么必须存在：

- 人必须保留最终判断权。

可以删除的功能：

- 复杂审批流。
- 多人协作。
- 评论区。

### 页面5：规则沉淀与导出页

用户在这里做什么：

- 查看本轮最终候选清单。
- 查看 AI 常见错误。
- 批准新增规则。
- 导出候选书清单。

AI在这里做什么：

- 总结本轮准确率。
- 生成新增规则建议。
- 生成下一轮选书重点。

为什么必须存在：

- FREETEXT OS 的核心不是一次性回答，而是把经验沉淀成系统。

可以删除的功能：

- 复杂报表。
- 会员系统。
- 销售预测。

| 功能 | 是否P0 | 说明 |

| 推荐理由 | P0 | 必须让人知道为什么推荐 |
| 风险提醒 | P0 | 标记库存、版本、供货、信息不全等风险 |

## 9. AI判断规则 v0.1

### A：强烈推荐

适合：

- 高度符合自由文本气质。
- 文史哲、文学、社科、非虚构、艺术方向明确。
- 作者、出版社、主题都较可靠。
- 可作为本月重点候选。

### B：可以推荐

适合：

- 方向基本符合。
- 有上架或推荐价值。
- 需要结合库存、定价、陈列主题判断。

### C：谨慎观察

适合：

- 有一定知识价值。
- 但可能过于学术、过于小众、供货不确定、中文版本未确认。
- 暂不直接进入采购。

### D：不推荐

适合：

- 纯流量。
- 低质鸡汤。
- 过度营销。
- 与自由文本气质明显不符。

## 10. 必须人工确认的信息

以下信息 AI 不能假装确定：

- 是否库存重复。
- 实际供货情况。
- 最终定价。
- 最终出版时间。
- 中文译本是否存在。
- 译者质量。
- 装帧质量。
- 门店当前是否已有同类书过多。
- 是否符合本月陈列主题。

AI可以提醒，但不能代替最终确认。

## 12. 原型中的核心按钮

第一版只需要少量按钮：

| 按钮 | 作用 |
| --- | --- |
| 开始本月选书 | 启动本月流程 |
| 生成候选书 | AI收集候选池 |
| 重新生成 | 当候选池明显不对时使用 |
| 标记同意 | 人工认可AI判断 |

| 标记不接受 | 人工否定AI判断 |
| 生成最终候选清单 | 输出本月结果 |
| 沉淀本轮规则 | 把反馈变成规则库 |
| 导出 | 导出给采购/内部使用 |

## 14. 不做什么

第一版坚决不做：

- 自动采购。
- 自动库存同步。
- 自动替代人的最终判断。
- 复杂供应链系统。
- 复杂会员推荐。
- 复杂销售预测。
- 复杂图书数据库。
- 多人协作审批。
- 社区。
- 内容发布平台。

## 15. 最小可交互原型建议

```text
顶部：本月选书状态

中间：候选书列表
右侧：单本书AI判断详情

↓

↓

↓
最终清单区
↓
规则沉淀区
```
